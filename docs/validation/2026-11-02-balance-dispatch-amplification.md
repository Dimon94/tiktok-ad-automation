## 根因与修复

前版 7b0a2d7f 的报表批量发布确实减少了发布耗时，但十五分钟观察遗漏了半小时周期造成的持续放大。11月2日余额 ACTIVE 248 批、剩余账户引用 404147，同账户最多60批。全队列共享的后台调度锁内，余额候选先展开252668条关联再选一批；空成本结算也走历史主键。

本版：周期余额计划复用同租户/操作者/冻结路由且整批 owner 有效的未完成账户；完成后下一周期继续刷新。没有新缺口则不再逐账户加scope锁。在途页码、冻结revision、请求时间和缺失余额语义保持。新增账户按实际集合创建幂等批次。余额候选改为执行FIFO、相关存在性探测与 LATERAL 逐候选持锁，保留租户公平、后台池窗口、配额及原子outbox。成本结算按现有 `(tenant, physical_endpoint, id)` 脏收据索引顺序读取，收费公式不变。

新增 `scripts/compact-balance-runs.py`：默认事务回滚预演；`--apply` 才提交。仅取消无有效租约且被同范围更新批次完整覆盖的旧批次；逐项验证冻结revision/时间和owner，保护后继租约。取消标记 `balance_superseded`/`SUPERSEDED`，不更新事实或满足水位，不退款未知成本；旧消息仍受终态/代数围栏及现有outbox清理保护。每批独立事务，statement timeout 5s、lock timeout 200ms、默认60s预算。
