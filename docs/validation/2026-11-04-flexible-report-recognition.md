# 自由命名与报表/经营归属联动核验

用户确认广告命名可自由排列，包括剧名在版权方标识之前，要求检查广告报表和经营看板。已核对现有策略命名字段、冻结预览、真实搭建回执、目录名称审计、广告报表当前名称投影及经营归属链路。

## 发现及处理

- 策略已支持独立字段及自由分隔符。工具内系列已有结构化识别：广告报表通过tenant＋account＋实际远端系列ID关联BuildUnit和PreviewDrama，读取冻结标题/标识；经营看板通过同一实际回执关联规范ProviderDrama与版权方连接。两者不依赖字段顺序，也不根据当前已修改的策略模板反推历史名称。
- 发现漏项：append_campaign_name_projections原先仅在名称或parser_revision变化时读取搭建身份。目录先到、回执后到时，名称不变会永久复用最初错误的字段拆分。已改成每批有界检查实际搭建身份（只读取身份窄列，不加载完整执行/预览正文），发现身份变化时追加名称/归组审计并由已有触发器更新campaign_name_current；原始广告名称、已发布审计及广告金额不改写。
- 同名重复同步保持幂等。没有新增身份依据时保留已有已解析审计，避免回退成错误位置解析；平台改名不匹配冻结名称时仍不强套原冻结标题。历史外部标准格式才使用既有位置规则，没有冻结信息的任意拼接名称不能无依据猜测。
- 经营看板原有回执映射已支持自由组合，本轮新增直接联动验证，无需再实现一套按位置拆分或修改经营公式。归属核对保留租户、账户和BC边界。

## 本地验证

使用专用本地PostgreSQL；外部服务为原测试边界，不调用真实TikTok、版权方或生产接口。

- 5种模板×普通/完整归因标识×回执正常/晚到，共20个真实预览/提交展开/目录投影/经营映射联动用例通过（16.45秒）。覆盖剧名在前、下划线、双冒号、斜杠、无分隔符及花括号归因标识。回执晚到问题先复现失败再修复；测试使用不同标识和剧名，避免同名夹具掩盖字段互换。
- 广告目录、报表查询、经营模块及策略命名147项回归通过（26.46秒）。另补已解析身份在回执暂不可用时保持审计的真实PG用例，目录模块15项通过（1.21秒）；最终身份窄列查询实现下21项联动/保留身份复验通过（21.43秒）。
