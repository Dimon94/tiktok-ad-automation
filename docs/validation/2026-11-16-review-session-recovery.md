# 复盘模型错误分类与有限新会话接续

## 问题与修改

针对[13:00两轮模型中断调查](2026-11-16-review-model-interruption-investigation.md)，修复模型拒绝继续会话后立即失败、错误细节全部变成通用提示的问题。方法正文仍为1.9.0；本轮更改运行逻辑，不改冻结方法、模型选择或业务证据。

- 原生模型错误区分会话拒绝、上下文限制、认证、配额、限流、参数错误、传输、超时、服务异常及未知原因。页面失败摘要记录固定分类及中文说明，运行日志关联任务编号；不将代理/模型错误原文或潜在秘密写入公开结果。
- 会话拒绝、明确上下文限制、传输/超时等中断最多新建两次Agent会话（总计最多三次），不在已拒绝的旧会话盲目追加消息。认证/配额/限流/参数/未知错误直接结束，未识别的策略拒绝不自动绕行重试。不切换模型或供应商。
- 接续仍使用同一任务、tenant/optimizer/fence、原模型、冻结证据和方法，沿用原心跳及两小时上限。每次接续前同步向服务端续期/检查权限；取消、撤权或fence失效立即停止，不创建后继模型会话。
- 同一领取过程保留成功工具工作账本、诊断及草稿自检阶段；新会话重新读取方法与已保存笔记，优先补缺口，不要求重新做所有已成功分析。定位摘要保留来源ID与原请求，避免错误地将分析产物ID交给只接受原始来源ID的读取工具。分析/时序/回放沿用同任务缓存读取入口。
- 接续定位信息有128条/12,000字符上限；不重复注入旧的约56KB诊断全文。定位裁剪独立于完成工作账本，不因提示裁剪抹掉已完成工作；引用仍由原成功凭证与领域API验证。
- 已完成结果保护保留：即使提交成功后的最终模型请求报错，也不重建会话、不再次提交或覆盖COMPLETE。

## 适用边界

这次实现的是**同一次领取内**的模型中断恢复。Worker/DSH进程被重启时仍走既有租约/fence恢复：冻结来源、缓存产物、凭证和笔记保留，但当前进程的内存工作账本会重新建立；未实现跨进程自动还原完整账本，也未改写历史FAILED任务。历史失败任务需要通过现有受权重启接口重新领取，已完成的数据准备不会重新拉取。

上游网关为何拒绝当前会话仍需其原始响应/请求日志确认。本轮没有将`PI_AI_ERROR`一概认定为上下文超限，也不承诺更换会话一定能够解除上游拒绝。达到接续上限后显示明确分类并保留证据，而不是无限循环。
