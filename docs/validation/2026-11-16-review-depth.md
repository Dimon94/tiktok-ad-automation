# 复盘逐日诊断与结论校准

## 已定位的问题

1. 1.7.1首稿核验投影使用all_totals，但成功分页响应实际返回totals，遗漏IAA等诊断提醒；修复真实响应合同，并优先保留全范围/逐日诊断，避免排名页挤掉关键证据。
2. 只有成熟窗口汇总和候选回放，缺少固定口径逐日结构分析；不能判断回收变动是覆盖、首次观察对象、低消耗层还是既有对象变化。
3. 正文限制没有约束摘要，出现把少数候选结果推广成控损上限、把素材假设写成根因。方法核验分别针对headline/summary/verdict/rule_decision，不能用正文一句免责声明抵消。

## 实施范围及合同

新增任务内tkada_analyze_timeline/API，基于原35日冻结campaign/material日事实流式汇总最后2–14当地完整日，币种/时区/窗口分区。返回逐日消耗/捕获收入/ROAS/损耗代理、按前日累计的低效/长尾/交集，以及首次观察消耗/既有低消耗/已证明回收/其余/未知分层。同账户每日均有有效配对数据的balanced_panel排除账户覆盖变化；不固定对象、流量或收入成熟度，不证明因果。

只用冻结历史，首次观察不冒称首次上线或新剧；缺收入不补零，缺身份/前史记未知；完整但无行的账户不混入固定样本。原归档无逐日IAA，明确NOT_FROZEN；不以D0/D3/D7不同窗口代替日趋势。新工具逐账户验证来源摘要及账户身份，引用使用新任务交付凭证；长分析不持有任务锁，提交前重验fence/版本/账户授权。分页输出<=64KB，缓存和产物受tenant/optimizer/task隔离。

Skill 1.8.0新增竞争解释→下钻→候选或业务验证的方法，将CONFIRM与验证证据分开。没有数据表或DDL/配置/资源/并发调整，不采纳/拒绝提案、不执行广告操作。发布沿用共享锁、正常退出、应用及DSH同SHA镜像更新、保持现有配置；按既有用户要求不创建/检查/替换备份、不恢复演练。
