# 解析准备的独立资源并行读取

状态：本地实现与验证完成，未推送或发布生产。基线 `8bf0d66d`，接续 `fe3b3cdc` 的等待优化；本轮提交主题 `builds: read independent scene resources concurrently`。

用户明确要求“不是必要串行的都不要串行，尽量并行”。上一轮只是去掉固定等待并连续执行，五类请求仍然串行，本轮补齐实际 HTTP 并行。

## 最终行为

- 身份、小程序目录、CTA、VBO 和地区按独立资源调度；同一场景任务最多三个 HTTP 同时执行，并取现有应用、租户和账户并发上限的较小值。Redis 中的真实在途、端点额度和平台限流仍逐请求原子准入，没有扩大配置额度或增加 Worker。
- 小程序目标尚未确认时也并行读取账户公共资料，Mini 目录优先进入窗口；不能猜测或自动替换目标。目标确认后，已有小程序目录及四类公共资料全部复用，避免选择后再串行补读。
- 每个线程使用独立官方 gateway/SDK 会话和短数据库事务，继承父任务诊断上下文；不共享 SQLAlchemy Session，不持行锁等 HTTP。SDK/MCP 的每次物理发送前及每页保存前仍核验 tenant/BC、完整冻结路由、角色和全局 claim/代数。
- 主线程按实际完成顺序逐页提交成功事实；任一资源失败不抹掉其它成功页，下一轮只读取未完成资源。同一列表的下一页必须在上一页保存后才能启动；缺页或重复 ID 不能通过完整性校验。
- 整轮最多五页，八秒后不再启动新读取，所有请求共用原四十秒工作截止时间。离开线程池前收齐已启动读取，重复消息不再次发送，Worker 中断后按已提交页恢复。
- 身份和小程序选择器按各自的完整计数及末页证据判断就绪，不再等待另一个较慢资源的阶段游标。手动刷新按原账户、租户/BC/冻结路由范围使全部有效场景缓存过期，不遗漏游标仍在 identity 的先返回目录。24 小时缓存期限与用户选择保持。

版权方取链已在 prepare 启动事务中独立排队，与账户能力准备并行；不同剧目和账户各有任务。保留真实依赖：权限核验在物理读取前完成，登录后才查询应用，确定剧目后才查询/创建其推广链接，发送效果待核实时不能跨过回读。

## 验证与边界

使用本轮独立 PostgreSQL 18 和 Redis 8。外部替身只放在官方 SDK/MCP 的 HTTP 边界，不调用真实 TikTok 或版权方服务。

- 原实现的请求重叠、失败后保留其它四类成功页、分页不阻塞其它资源三个测试先失败；三请求重叠由传输层 Barrier/Event 证明，不以任务数量冒充并发。
- 新增测试覆盖：并行及最大窗口、重复投递、无网络期间行锁、部分失败仅重试缺失项、同资源分页依赖、账户配额为一、权限变化拒绝发布、中断保留成功页、未知目标提前准备及选择后零额外请求。
- 扩展初轮 259 项回归为 254 passed / 5 failed。两项等待状态问题通过在领取时重算首个缺失资源修复；两个重复分页用例改为先真实完成身份阶段，避免只改游标冒充前序事实；一个缓存搜索夹具补齐与 51 条完整分页相符的 seen=51。没有削弱分页或权限校验。这五项修正后均已在相应定点组复验通过。
- 最终核心组（并行、服务、恢复、超时、重复分页）39 passed / 72.24 秒；目录显示、刷新、搜索组 12 passed / 57.59 秒；补齐未知目标提前读取后，最终并行、服务与双通道组 36 passed / 98.74 秒。各次测试存在重合，不累加为独立用例数。
- 三个源文件 `scene_jobs.py`、`scene_reads.py`、`mini_selection.py` 严格 mypy 通过；本轮 Python 文件 Ruff check、差异空白检查通过。本轮没有前端或客户端合同修改，不重复运行上一轮已通过的前端构建与浏览器全量测试。

没有新增数据库字段、迁移、持久任务正文字段、队列或业务开关，但持久进度从固定顺序变为可乱序保存、游标指向首个缺失资源。发布前必须审查这一数据语义变化，按部署手册选择具体切换方案：旧资源 Worker 应退出后再消费新版未完成任务，API 目录读取与资源 Worker 应使用相同版本，不能让旧串行消费者或盲目回退版本接手乱序断点。本轮没有执行生产切换或备份操作。
