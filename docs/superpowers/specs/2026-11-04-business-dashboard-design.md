# 经营看板：T+1 日核算与三种补贴情景

状态：用户2026-11-04已批准本设计及补充默认；实施中，尚未发布。

## 目标与已确认范围

- 在 TK-ADA 增加经营看板，沿用周报、日报的平台与经营口径；按广告系列、剧目、版权方查看与筛选，支持日期筛选及导出。
- 仅使用系列日指标及其向上汇总，不查询素材指标、不增加素材维度。不显示当天，采用 T+1 更新。
- 顶部五张卡片：平台消耗、平台收入、平台 ROAS、经营收入、经营 ROAS。
- 列表补充版权方分成、分成后收入、其他返点、预计赔付及三个独立补贴情景：新开 A 漫剧、新开 A 其他剧、在投闭环 B。
- 补贴及赔付只展示预计金额，不实现平台判定、实际到账、支付或补贴状态列。计算缺口必须可识别，不把未知写成零。
- 版权方抽成在版权方连接中配置，每个租户独立，默认 0%。其他返点统一为一个比例，无须拆代理和主体等明细。
- 用户确认 Q4 与 Q3 新剧政策相同；三个补贴情景都算，不要求先判断剧目实际属于哪一类，情景之间不相加、不自动取最大值。
- 用户同意：先按剧的政策周期累计消耗计算补贴，系列视图按剧季度内系列消耗占比分摊，标为分摊预估；每日只计补贴变化额，避免重复累计。

## 现有工程依据与限制

- `backend/app/modules/reporting/store_models.py`：`CampaignReportDay` 已保存系列日报，由广告日报在发布事务中汇总；不是独立采集的系列原始报表。本功能直接复用，不改变现有同步数据源。
- `reporting/planner.py` 已有近期32天回刷及开户以来历史回填；现有历史规划同时包含广告日和素材日，不能为本功能原样再触发一轮素材回填。已有日报优先使用，缺口按账户日期补齐必要来源。
- `reporting/read_models/dirty_buckets.py` 已有来源修订与派生水位，可复用其并发原则；经营投影须有自身水位，不复用其它投影的完成标记。
- 现有系列/剧报表、版权方连接、异步导出提供基础能力；现有剧名解析不等于可靠财务归属，必须补稳定映射。
- 2026-10-21历史性能记录出现约七万系列目录及数百万关联记录，只能证明应避免全明细反复扫描；本轮未查线上最新表规模，未给出回填耗时承诺。
- 本地周报计算器有 USD/UTC 与人工激励输入限制，不能直接作为本功能的多租户、多时区核算引擎。

## 方案比较

| 方案 | 取舍 |
| --- | --- |
| 查询时扫描明细并核算 | 配置变化即时，但大日期范围慢，赔付证据及跨期补贴计算不适合请求内执行 |
| 每天全历史重算 | 查询快，但计算浪费，租户变多后挤占同步任务 |
| 日核算表、按变化重算、查询轻量汇总 | 选用；满足 T+1，已有历史可批量生成，费率及事实修正仅更新影响范围 |

不增加分析数据库、独立常驻服务或部署级布尔开关。先复用 PostgreSQL、Beat、现有任务编排及合适队列，具体队列与批量大小由实施计划确定并量测。

## 页面与计算口径

新建经营看板入口，复用当前 shadcn/ui 组件与已批准统一视觉规范。提供系列、剧目、版权方三个分组方式，默认剧目；支持版权方、账户、日期、关键词筛选。BC 沿用当前工作台明确选择，首版不新增跨 BC 合并入口。

默认查询最近7个完整日。账户当地日期决定是否完整；混合时区默认截止选中账户共同完成的最近日期，不查询未来或盘中。展示日期口径、事实更新时间、计算完成时间及覆盖范围，不声称日结束后收入永久固定。

设单行消耗 C、平台总收入 V、版权方抽成 r、其他返点比例 b：

```text
版权方分成 = V × r
分成后收入 = V × (1-r)
其他返点 = C × b
基础经营收入 = 分成后收入 + 其他返点
平台 ROAS = ΣV / ΣC
基础经营 ROAS = Σ基础经营收入 / ΣC
情景经营收入 = 基础经营收入 + 预计赔付 + 所选情景补贴增量
情景经营 ROAS = Σ情景经营收入 / ΣC
```

五卡默认采用基础经营口径。提供“基础 / 含预计：新开漫剧 / 含预计：新开其他剧 / 含预计：在投闭环”切换，仅改变经营收入与经营 ROAS 卡片。列表一直保留预计赔付、三种补贴列；补贴列名或说明明确“区间预计补贴增量”，剧详情另给季度截至查询截止日的累计预计。

所有卡片、列表排序、筛选、分页和导出使用同一筛选集合及计算版本。合计基于全筛选集合，不能只合计当前页。金额 Decimal/NUMERIC 全精度计算，最终显示两位；ROAS四位，比例两位。消耗分母为0时显示“—”。不同币种分开展示，不默认换汇。经营收入不是现金到账或公司净利润。

未知指标、缺失来源、未归属剧目分别保留；可显示已核算小计和缺口提示，但不能标为完整总额。版权方已存在且无抽成版本时使用明确的产品默认0%，不是未知；连版权方都无法归属时不能擅自认领到任意连接。

## 配置、身份与历史版本（以下为设计默认，待本稿批准）

### 版权方抽成

版权方连接编辑页增加百分比及生效日期，默认0%。版本归属 `tenant_id + provider_connection_id`，不可跨租户复用。每次修改保存生效日期、操作者、创建时间，历史版本不可覆盖。相同连接同一天仅允许一个有效版本，通过修订记录替换而不是保留重叠有效区间。

默认从下一完整业务日生效，用户可选择更早业务日期追溯；保存前展示影响日期及回算范围。业务日期均指账户当地日期，界面说明混合时区不是同一UTC窗口。没有更早版本的日期按默认0%计算，用户可从历史起始日补录。

同一版权方多个连接的业务合并，必须有显式租户内版权方标识和映射；首版默认连接独立，不因显示名相同合并合同。

### 其他返点

经营设置按 `tenant_id + bc_id` 保存一个合计比例及生效日期，默认0%，同样版本化及允许追溯。不拆代理、主体等子项。经营报表仅租户管理员及平台管理员可以查看、查询、重算和导出，普通操作员及读者无权访问。

### 剧目归属

2026-11-04 用户追加澄清：经营看板沿用广告报表的版权方标签＋剧名解析，不能仅因剧目没有进入搭建剧库就丢失经营金额。优先采用人工归属/搭建回执及规范剧库ID；历史系列按同一 `parse_campaign_name` 解析，将版权方标签（含已核实的刚刚好历史简称）唯一匹配当前租户连接，按生效分成核算。剧编号明确且无冲突时使用版权方连接＋编号形成稳定历史身份，剧库补齐后统一重算归并；目录中的重复编号/多连接匹配不任取。仅有名称时沿广告报表按版权方＋剧名归组，基础经营仍可核算，但不将无可靠剧编号的应用/合集名称用于新剧补贴门槛。

已在剧库内的同名/改名优先使用规范ID；跨版权方同名不能合并。无唯一版权方连接时只显示解析标签及名称，经营金额保持空并在按需说明中提示。

系列归属按账户+系列ID保存，可追溯修订；目录改名不改变历史业务身份。未知历史系列允许人工归属并触发重算。一个系列跨剧或映射冲突时不任取一部剧分配，记录缺口待管理员处理。

业务事实按现有租户+账户+对象+日期存放，不因账户可见于多个BC而复制源事实。首版查询一次只选择一个BC，并按其明确返点及政策范围核算；不将多个BC的重叠账户结果直接相加。

以下为独立审阅后补充的设计默认，待本稿批准：

- 新剧补贴首版仅支持USD政策，不引入汇率。如果同一剧目的政策核算范围含非USD消费，三个全范围补贴情景保持NULL并说明币种缺口，不把USD子集伪装成完整累计；基础经营仍按币种展示。未来支持换汇需独立制定汇率和历史版本规则。
- 页面基础经营截止日依所选账户判断；补贴每日完整性依全部政策范围成员判断，包含未在页面选中的账户。如果更大范围尚未结束该当地日或来源缺失，基础经营照常显示，该日及受累计缺口影响的后续补贴显示“—”，不以未完数据匹配档位，也不为补贴静默改变整页日期。
- 政策范围成员必须保存有效业务日期和版本。首次初始化以当前已授权BC账户建立明确成员清单，初始有效期覆盖本次选定历史起始日，仅表示本系统条件预估范围，不证明历史BC所有权。后续新增账户默认从纳入业务日开始贡献，移出从指定业务日起停止贡献；均不静默改写之前归属。需把新增账户更早季度消耗纳入时，由管理员明确选择历史生效日并触发季度回填/重算。范围变化、来源变化和政策变化一样进入计算版本。
- 撤销授权不是自动把其历史消费清零或分摊给剩余账户。查询及导出继续执行当前账户权限；若可见剧补贴依赖已无权访问的成员，该补贴聚合不对当前用户展示，避免通过结果泄漏隐藏成员数据。已冻结导出同样重新核验，不凭旧权限下载。

### 每日增量与系列分摊

按规范剧目+政策范围+季度保存每天截至当日的累计消耗 S(d)，三个情景累计预计 P_j(d)=tier_j(S(d))。每日增量 ΔP_j(d)=P_j(d)-P_j(d-1)，季度首日之前基准为0；查询区间[a,b]只汇总区间每日增量，不把截止日累计值每天重复加一次。跨季度独立计算，最后再汇总。

系列分摊使用截至业务日d的季度累计消耗权重：w_c(d)=S_c(d)/S(d)，系列当日分摊增量为 ΔP_j(d)×w_c(d)。这样单剧所有系列的每日金额加总严格等于当日补贴增量，零消耗系列不分摊。系列局部筛选只展示其分摊份额，不重新计算全额补贴。内部保留完整精度，导出显示舍入差按稳定系列键归入尾差，不能改变剧补贴总额。

历史事实或剧目归属修正，重建受影响季度从最早变更日至季度末/最近完整日的累计、跨档增量及权重，允许金额下降，不截断负向调整。比例变更不影响补贴门槛，不无故重算政策累计。

首次查看某月必须具备该季度此前数据才能给出正确增量。回填优先最近30天时，应同时补齐所在季度起点至该窗口前一日的补贴所需基础；未齐时基础经营照常查询，补贴显示“—”并提示覆盖缺口，不能把窗口起点当作首投日。

## 预计赔付

按政策规定的系列日核算，再向剧目及版权方汇总。使用D0收入，不用平台总收入替代；不能先按剧或月份合并后算赔付。预计口径复用周报参考 `compensation-estimate-and-reconciliation.md` 的逐日出价和负向操作规则，实施时再次验证当期官方规则及支持的产品结构。

当前已有参考模型：适用的CBO Mini Dramas、D0 IAA tROAS，IAA事件≥300，B×C>1.2×V0才触发，P=max(0,C−V0/B)。B为有证据的当日适用出价；没有适用资格、历史出价或排除操作证据时不能称完整核验结果。非CBO、其它产品结构不套此公式，保留不支持/缺口元数据。

前台只显示预计金额，不增加资格/到账状态列；计算条件及缺失依据放在金额提示与数据覆盖说明中。确定不触发时为0，缺关键输入时为NULL并显示“—”。预计赔付独立于三个新剧补贴情景，不据新剧类型重复计算三份赔付。

经营看板不查询素材指标；如赔付规则需素材拒审等资格证据，只保存必要资格事实，不加载素材表现报表或扩展素材列表。缺证时保留条件预估边界。

## 数据合同与更新机制

新增独立经营模块，保留以下逻辑合同，具体表名/拆分由实施计划决定：

- 费率版本：租户、连接/BC、生效日期、比例、修订与审计。
- 业务归属映射：租户、账户、系列、规范剧目、版权方连接、有效修订与来源。
- 政策版本：适用季度、币种、核算范围、三个档位表、赔付规则及依据。
- 系列日经营投影：基础业务键、币种/时区、来源修订、映射/费率/政策版本、平台指标、分成、返点、基础经营、预计赔付、三种分摊补贴增量及缺口元数据。
- 剧目季度日累计与剧目/版权方日汇总：记录计算水位，可从来源重建，不作为独立手工事实修改。
- 计算任务/发布代数：输入范围、修订、检查点、租约、进度、错误及重试。失败日期不会标为已覆盖。

任务只在完整来源发布后计算，不能把同步失败或部分页当0。Beat每日触发有界任务，按账户当地日完成情况与来源覆盖确定范围；不按固定北京时间推断所有账户都已结束昨天。近期源事实回刷时记录受影响日期，下一轮T+1计算统一吸收；默认每日一次经营发布，不额外为本看板启动盘中热刷。

首次回填优先近30个完整日，经营基础优先可用，季度补贴前缀独立补齐；更早历史按月后台执行。计算与缺失数据采集分开，采集沿用官方SDK及既有租户/BC授权、配额、公平调度，不挤占正常同步全部容量，不新增素材任务，不对每次页面访问发平台请求。

追溯修改、来源修正仅标脏受影响范围，去重同范围任务。后台先构建候选代数，完整核验后原子发布；重算过程中旧已发布版本仍可查询并显示截至时间，首次无旧版本的范围显示待生成。每个被查询范围使用一致已发布代数，不能混合新旧分成、补贴或卡片。并发任务只能确认自己冻结的来源修订，迟到旧任务不得覆盖新结果。

按租户、账户、日期及系列建立索引，系列日投影按月分区；版权方/剧目日期聚合用于卡片及列表，避免广告与素材级扫描及逐行查询。跨年大区间需量测后决定月汇总，不先引入额外存储系统。首次回填输出样本吞吐、剩余对象日与覆盖范围，据此估算耗时，不预先承诺分钟数。

## 导出、权限和查询一致性

复用异步导出基础设施，但需扩展为冻结完整数据版本，而不只冻结行成员。固定筛选、币种、分组、来源与计算版本、情景、排序、列及截止日期；后台按批读取同版本，源数据更新后不能导出一半旧值一半新值。首版优先CSV，复用公式注入保护。

经营看板菜单、页面与全部经营接口仅管理员开放。只输出当前授权租户、BC及账户；创建、执行、下载均重验当前管理员角色及账户权限，降权或撤权后不能凭旧链接下载。费率配置和追溯重算仅租户管理员可操作；平台管理员依现有代租户规则操作并审计。不导出版权方凭据、授权令牌或操作日志原始私密字段。

## 实施分期与验收
