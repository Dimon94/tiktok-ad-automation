# DSH 逐日控损回测

用户要求：现行规则从未执行或处于禁用状态，也须分析历史投放、回测当前规则和候选阈值，量化历史可拦截消耗/收入/亏损及误关风险，生成有证据的待确认修改。完成并发布生产，检查真实复盘。

约束：保持 main、租户/BC/账户授权、规则启用状态和现有部署配置；不执行广告动作；MANUAL 提案仅经人工确认发布。不创建/检查备份，不执行恢复演练。数据仍采用逐账户不可变归档与按需工具，不能将全量日明细塞入上下文。

1. 后端冻结逐账户日事实、覆盖、实体关系和绑定规则；复用生产条件语义逐日评估，明确日末决策次日生效。无执行历史亦可计算。逐分区输出基线、现行、候选的消耗、收入、ROAS、历史拦截金额及误关风险；覆盖不足和不支持条件必须明确，禁止未来数据污染与重叠重复计算。
2. 任务范围 API 与 DSH 工具接入；方法要求禁用规则也做基线回测，证据不足列具体缺口，结构化表格展示结果、有依据才提交可执行修改。
3. 真实 PostgreSQL 行为回归、插件原生测试及独立审查。测试涵盖零执行记录、缺失日、无未来泄漏、账户分区、候选比较及引用隔离。
4. 聚焦提交推送公司 main，精确版本发布应用及 DSH，保留配置。发起原50账户只读复盘，检查实际工具调用、报告及待确认项状态，记录生产真实结果和限制。

解释边界：历史拦截金额为对实际已观察数据的策略过滤，受已暂停对象的后续观测截尾影响；不是因果节省、未来预测或经营净利润。规则执行效果与反事实模拟分别报告。
