# 大范围 Agent 复盘改造实施计划

**Goal:** 单次工作台复盘覆盖绑定的全部账户，由 Agent 按需检索、聚合、读取证据并持久化中间结论，完成后发布生产。

**Architecture:** 小任务清单与大证据分离；账户证据后台分批准备并独立保存。Agent 从全局聚合到账户/对象明细下钻，读取账本独立存储，避免模型上下文、任务 JSON 和数据库证据容量混为同一限制。使用统一 Agent 而非强制每账户调用模型。

**Tech Stack:** FastAPI/SQLModel/PostgreSQL/Celery 与 DSH 原生插件。

## Global Constraints
- 保持 tenant/optimizer/BC/账户、版本、撤权和 fence 校验；开发无真实广告/素材写入。
- 保持完整自然日、成熟归因、币种与可用性口径；不静默丢账户，不将样本视为全量。
- 用户授权推送与生产发布，沿现有 main；无新备份、恢复演练或部署开关。数据库/任务合同改动选择明确增量迁移与消费者协调方案。
- 仅读实际来源数据，不夸大 Agent 与本地 Claude Code/Codex 判断质量完全相同。

## Review Focus
- 1000 账户索引/摘要不进入初始模型输入。
- 后台准备幂等续接、单账户错误可见、撤权或版本改变不继续。
- 读取/聚合结果稳定可引用，账本增长不撑爆任务 JSON。
- 聚合不跨币种、时区、归因和成熟资格混算；不让 Top N 排名替代全量分母。
- 长会话短令牌续期、到期恢复和中间笔记保留。
