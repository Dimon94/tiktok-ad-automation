# 同步控制面及查询投影迁移手册

状态：2026-10-31 用户已授权完成必要修复后直接上线，在生产进行真实容量验证，不再等待独立全量压测空间；并明确选择停旧后整体切新版，不保留长期旧逻辑兼容。**授权不代表已经发布或性能达标**。仅全停旧消费者后整体切换，不与不识别新围栏的旧程序混跑。最终以验收记录的候选 SHA、Alembic head 和实际配置为准。

本次选择：本地保留已有正确性验证及必要的小规模定向回归，全量容量和持续服务率转为上线观察。保留历史事实、任务ID、暂存页和断点，迁移仍通过Alembic及有界映射工具完成。按用户现行策略不自动创建备份或执行恢复演练；新合同写入后只能暂停相关处理并前向修复，不能直接启动旧镜像。上线前仍须查清生产存储余量，未知容量不等于有足够空间。

2026-10-31后续已从控制台核实实际实例180GB、使用122.82GB，自动扩容开启且上限64000GB；容量未知停止条件解除。本次从0069开始逐版本调用Alembic升级至0099，每个版本提交后记录结果，减少中间索引重建的同时占用；任一步失败保持应用停写，核对已提交revision后前向续接。平台额度、物理Worker并发及四开关保持原值，持久background池选用4/12（容量/额外预取）。

## 准备与停止点

1. 保存精确旧镜像/候选 SHA、当前 Alembic revision、四项业务开关、真实 app 额度策略摘要及各队列角色预算。不输出密钥。备份按用户当前按需策略，不将未执行的备份或恢复演练写成已完成。
2. 核算源表、六类派生表、索引、临时暂存及 WAL 峰值。只用源数据实测估算，不以空库大小推断生产。核对生产盘余量和维护窗口；不能把本地缺少压测磁盘的豁免延伸为忽略生产迁移容量。空间不够或余量未知时在停服前停止。
3. 停止 API 写入/外部任务入口、Beat、旧 Control 与所有同步消费者，按部署手册正常退出和排空；不清空 Redis/outbox。核实旧进程及未结束数据库事务为零。尚有效的租约等到正常结束/到期，不直接改过期时间。
4. 切换前审查迁移 SQL、已完成的正确性与局部压力结果。未完成千万规模与24小时压力结果按本次授权转到生产观察，明确记录未验证，不把它写成通过。迁移、授权隔离、恢复游标及金额/关联正确性仍必须验证。

## 迁移与映射

环境文件必须经 `config/README.md` / `config/environments.json` 定位。以下为已选定流程的命令形状，`$APP_ENV_FILE` 必须由操作者明确设为目标环境，禁止使用默认 `.env`。命令在 `backend/` 执行。

```bash
uv run alembic current
uv run alembic upgrade head
uv run python ../scripts/sync-query-cutover.py --kind all --output /approved-artifact-dir/cutover-inspect.json
uv run python ../scripts/sync-query-cutover.py --kind all --apply --consumers-stopped --batch-size 100 --max-batches 100 --output /approved-artifact-dir/cutover-map.json
```

- inspect 只读，检查活动执行是否已经映射。apply 逐批提交；每批完成才记录游标，中断后从头重跑也是幂等。
- `mapping_complete` 仅表示没有未映射的活动任务、且已映射余额的旧版未发送消息均已退役，不表示整站可以恢复流量。
- 有效租约记为 deferred；未知账户/非法冻结路由/无剩余范围记为 error，保持原任务及页。必须处理原因后重跑，不能删掉这些记录来通过检查。
- report 保留原任务ID、全部私有页与progress，按账户/日期建子桶；directory保留next_page、observed_at和页；balance只登记remaining账户，保留分页。
- 余额新消息必须携带派发时持久化的 claim_id/generation。迁移将精确旧版载荷且已映射的未发送消息标记 superseded_at，保留原正文、摘要及未发送状态；不会伪造 published_at，不清 Redis。已进入 broker 的旧消息被新消费者拒绝，不会读取平台；持久到期头重新派发具备围栏的新消息。
- 已执行冻结查询不扩范围；新增需求由后继承接。切换后旧claim token失效，不能借迟到消息发布。

### 共享后台 Worker 预算

0088将历史事实、历史关联、目录全量读取和余额读取纳入同一个 `background` 池；实时读取与本地发布继续走各自队列。必须逐项核对实际队列消费者，不能以Deployment名称推断职责。当前生产清单的 `ads-backfill,ads-directory` 共用4个进程，`ads-publish` 的单槽是本地发布角色。

池中 `capacity` 表示实际后台进程预算，`prefetch_slots` 是除此之外允许排队的工作量；它们不增加平台QPS、不改变Celery并发。默认4/0只是结构初值，最终值须以同队列混合负载实测决定。预取过小可能使页间空闲，过大则扩大等待与过期重派，因此4+12在两组反序真实transport边界混合测试中未见吞吐下降，本次按已授权整体优化选用4/12；不是生产吞吐保证。

只有停止全部旧消费者并完成 `--kind all` 映射后，才可在同一切换命令增加 `--background-capacity N --background-prefetch-slots M`。命令拒绝只读模式、部分kind及越界值；映射未完成时不会应用配置。输出中必须同时核对 `mapping_complete`、`background_pool.source` 及 `configuration_applied`。不传这些参数保留既有配置和公平游标；重新执行不会重置公平状态。调整实际Worker数量时也须同步核对该持久预算，不只改Deployment。

## 投影回填与核对

`app.modules.reporting.read_models.rebuild` 提供目录/命名/素材当前引用的500条游标回填与日期范围派生重建；每批独立提交，重复执行重读当前规范事实，不能用旧导出覆盖新版本。按实际 CLI `--help` 选择账户范围，保留每个账户/种类的恢复游标。派生必须经过dirty版本围栏。

核对至少包括：

- 各租户/账户/币种/日期的事实行数与精确金额，不只总量；空、零、不支持指标分别核对。
- 当前素材类型、同一视频多个帖子、同版本不明确引用、晚补关联、历史名称及轮播图片。
- 查询固定成员/排序/summary T0，最新页指标时间和BUILDING/STALE真实显示；不能把未派生桶显示成完整零金额。
- 所有活动旧任务有对应未满足需求与子桶，页/游标未丢；terminal错误保留未满足意图及原因。
- dirty积压下降、投影服务率覆盖到达率；不足时不能启动全部同步入口制造新的派生积压。

## 恢复与回滚边界

按最终预算先恢复新执行消费者、Control/结果，再恢复Beat和API入口，核验各角色运行同一版本。验证目录/报表/余额及跨日真实链路；从实际 oldest_age 和成功数据产出判断，不以队列短暂变空或worker在线代替业务成功。

新消费者启动前可停止迁移、保留旧镜像与尚未改写的规范事实。**新程序已经写入后，禁止直接降 Alembic 或启动旧消费者接同一队列**；应保持写入口停止，选择已演练的数据恢复或前向修复方案。回滚工具不清空队列，不删除未完成需求。

至少记录3×15分钟趋势，并继续24小时/账户跨日/余额周期观察。这些是上线后的待执行验收，开发本机测试不冒充生产观察。

## 生命周期与运行观察

- 业务发布不执行分区DDL；月分区维护短事务独立执行，200ms锁等待/5s语句预算，争用时延后。DEFAULT日期索引帮助维护定位。
- 暂存页有界清理；有PENDING子桶、有效claim、未结算成本时保留恢复证据。终态摘要90天后通过独立私有`SYNC_ARCHIVE_BUCKET`归档，不能与素材桶同名；未配置或存储失败保留源记录。流程与失败恢复见[运行归档](sync-run-archive.md)。
- 成功报表分页保留1小时，失败/取消分页保留7天。成功页清理不等待outbox正文压缩，因为父任务和幂等身份仍然保留；未完成子桶、未结算成本、有效领取及租约继续阻止清理。该规则减少已完成大响应的重复留存，不删除报表事实或任务摘要。
- V2消息签发后7天过期，有效消费者结束后退役；退役后7天压缩正文、30天删除消息身份。消费者验证持久消息身份，迟到旧消息不能复活运行。旧合同仅压缩正文保留幂等摘要；不能直接对所有outbox套TTL。
- 原始小时金额停止旧30天删除策略；不按目录/任务保留期限删除财务事实。需另测长期事实增长及分区容量。
- 关注物理endpoint的queued/active/本地拒绝/平台拒绝，分别记录原因；不能把本地拒绝计成平台429。所有发送走现有额度账本。
- 0086成本账本观察实际SDK传输边界，按执行代数结算调度公平成本；本地准入拒绝计0次物理调用，已发送的平台拒绝仍计真实调用。它不承担平台配额扣减。尚未结束或未结算的账本保护父执行不被清理；未知崩溃不能直接当作0成本退款。
- 查询观察首屏完成时间、页读取、同时构建数、pool wait、WAL、临时文件与最老dirty年龄；20相同查询和20不同冷查询分开统计。
